# 社区论坛测试项目（公开版）

对一个 Flarum 开源论坛（PHP + MySQL + JSON:API）做功能测试、接口自动化、UI 自动化与
读接口性能测试。项目重点不是“把页面点一遍”，而是把**权限边界、限流策略、搜索缺陷**
用可复现的用例固定下来，并在报告中区分“用例失败”“预期失败”和“脚本误报”。

> 原项目在一个面向测试学习者开放的公开练习论坛上完成。公开仓库**隐去站点地址与账号**，
> 代码默认指向本地 Flarum 实例；如需在远程环境运行，必须设置 `FORUM_ALLOW_REMOTE_TESTS=1`
> 并确认已获得授权。请勿把本项目脚本指向未授权站点。

## 结果摘要

| 指标 | 结果 |
|---|---|
| 功能用例 | 51 条（9 个模块）；已执行 49 条，47 通过 / 2 失败 / 2 未执行 |
| 接口自动化 | 26 条：**19 通过 / 7 预期失败（xfail）/ 0 意外失败** |
| UI 自动化 | 6 条主链路场景，6/6 通过 |
| 性能测试 | 5 / 10 / 20 并发，合计 **8,750 请求，0 错误** |
| 缺陷 | **3 条**：P1 严重 2 条（中文搜索失效、登录接口无限流），P2 一般 1 条（发帖限流过严） |
| 用例维度合计 | 83 条，执行率 97.6%；通过 72，预期失败 7，真实失败 2 |

结果口径：

1. 接口套件开启 `xfail_strict=true`：只有**确实复现失败**的已知缺陷才计为预期失败；
   7 条 xfail = 4 条显式缺陷回归 + 3 条被发帖限流阻断的写接口用例。
2. 功能测试的 2 条失败与 BUG-001 / BUG-002 一一对应；BUG-003 的关联用例执行结果为
   “通过”（限流确实生效），但“阈值过严”作为独立缺陷另行记录 —— **用例通过 ≠ 功能无缺陷**。
3. 性能数据来自 2026-09-02 优化前脚本，之后未重跑；原始 `.jtl` 与 HTML 报告不随仓库提交。

## 快速开始

### 1. 安装依赖

```bash
python -m pip install -r requirements.txt
python -m playwright install chromium      # 仅 UI 自动化需要
```

### 2. 配置

```bash
# PowerShell
Copy-Item .env.example .env
# 编辑 .env：至少填 FORUM_BASE / FORUM_USER / FORUM_PWD
```

也可以不建 `.env`，直接设置系统环境变量：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `FORUM_BASE` | `http://localhost:8080` | 被测 Flarum 实例 |
| `FORUM_USER` | `testuser` | 普通用户测试账号 |
| `FORUM_PWD` | 空 | 账号口令 |
| `FORUM_ALLOW_REMOTE_TESTS` | 未设置 | 远程授权环境才设为 `1` |
| `FORUM_DISCUSSION_ID` | `1` | UI/性能测试的详情页靶点 |
| `FORUM_SEARCH_KEYWORD` | `123` | UI 搜索场景关键词 |
| `FORUM_TAG_NAME` | `测试技术类` | UI 发帖板块名 |

默认只允许 `localhost` / `127.0.0.1` / `::1`；这是为了防止脚本被误指向未授权站点。

### 3. 跑接口自动化

```bash
cd 03_接口测试/接口自动化

python -m pytest --collect-only -q      # 只收集，不需要登录
python -m pytest -m "not write" -q      # 只读子集
python -m pytest -q                     # 全部（写接口会真实发帖/评论）
```

> 写接口会在实例上产生测试帖与评论。运行后用 `python cleanup_api_test.py --apply`
> 按关键词软删除；默认不加 `--apply` 只试运行。首次运行建议先跑只读子集。

### 4. 跑 UI 自动化

```bash
cd 06_UI自动化
python run_ui_e2e.py
```

未配置账号时只跑首页/搜索/详情 3 个只读场景，登录、发帖、退出记为跳过。
UI 脚本会把过程截图写入 `06_UI自动化/截图/`（已忽略，不提交）。

### 5. 跑 JMeter

```bash
cd 03_接口测试/JMeter工程
jmeter -n -t forum_load_test.jmx \
  -Jdomain=localhost -Jprotocol=http -Juser=testuser -Jpwd='your-password' \
  -Jdiscussion_id=1 -Jkeyword=123 \
  -Jusers=10 -Jloops=50 -Jrampup=5 -l results_10.jtl
```

压测计划只压读接口，不压发帖写接口（受 BUG-003 限流影响，写压测会变成测限流）。
详细说明见 `03_接口测试/JMeter工程/README.md`。

## 关键设计

1. **权限类用例用“接口 + UI”双通道判定。**
   普通用户访问管理接口 / 删除他人内容期望 403；只有 UI 与接口结论一致时才确认，
   避免把 Flarum 的软删除、`canDelete` 等正常设计误报成越权。
2. **已知缺陷用 `xfail(strict=True)` 固定。**
   缺陷修复后用例 XPASS 会直接判失败，提醒回来销账；它不是永不失效的注释。
3. **区分“用例通过”和“功能无缺陷”。**
   BUG-003 的关联用例验证的是“限流是否生效”，第 2 帖即 429 说明限流生效，故用例通过；
   但阈值过严是另一层问题，单独记为缺陷。
4. **误报先排除再上报。**
   项目复核并排除了 3 处疑似缺陷（脚本取文本过早、UI 按钮与 API 权限两套判据、
   搜索命中正文但标题不含关键词），均未写入缺陷报告。
5. **测试数据可回收。**
   接口与 UI 清理脚本只处理“作者为测试账号且命中测试关键词”的内容，默认 dry-run，
   `--apply` 才软删除，并输出清理记录供复核。
6. **性能结论只描述本次观测。**
   压测在共享练习环境完成，无服务器权限；只保留“读接口随并发线性增长、搜索最慢”
   这类可迁移的观察，不把 TPS 当作产品固有限制。

## 公开范围与负责任披露

本仓库**不包含**：

- 真实站点地址、真实账号口令、Cookie / Token；
- `allure-results/`、`allure-report/`（附件含完整请求 / 响应）；
- 运行日志、缺陷截图、原始请求 / 响应记录；
- `results_*.jtl`、`report_*/` 等性能原始数据与 HTML 报告；
- 数据库备份、内网路径、内部交付说明、简历与面试准备材料。

仓库只保留可公开的测试代码、用例、脱敏后的结果摘要与缺陷摘要。完整复现记录与原始证据
留在私有目录；如需复现，请在自己的 Flarum 实例或已获授权的测试环境中运行。

被测系统 Flarum 的版权与许可归其原作者所有；本项目是个人测试实践，不代表被测站点或
Flarum 官方的质量结论。
