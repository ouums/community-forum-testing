## 3. 接口自动化（pytest + requests）

26 条：**19 passed，7 xfailed，0 意外失败**。

| 接口层 | 用例数 | 通过 | 预期失败 | 说明 |
|---|---:|---:|---:|---|
| 只读（登录鉴权/列表/详情/评论列表/搜索/标签/权限校验） | 20 | 17 | 3 | BUG-001 ×2、BUG-002 ×1 |
| 写（发帖/评论/改昵称） | 6 | 2 | 4 | 受限流阻断（BUG-003）；正常发帖、改昵称通过 |
| **合计** | **26** | **19** | **7** | 无意外失败 |

关键设计：

- 会话级登录一次，登录后立即请求受保护接口做**鉴权自检**；Token 未生效则终止会话，
  避免“读接口还能返回数据”造成的假通过。
- Flarum 认证头必须是 `Authorization: Token <token>`；写成 `Bearer` 时读接口仍可能返回数据，
  直到写接口报 CSRF 错误才暴露，因此自检放在第一个用例之前。
- 失败时自动把本次用例的请求 URL、参数、状态码、响应体附到 Allure 报告；日志对
  `Authorization` / `Cookie` / `password` / `token` 做脱敏。
- 只读子集：`python -m pytest -m "not write" -q`；写接口会真实发帖/评论，运行后需清理。

## 4. UI 自动化（Playwright）

6 条主链路场景全部通过：首页加载 → 数字关键词搜索 → 帖子详情 → 登录 → 选板块发帖 → 退出登录。

- 选板块：Flarum 的“选择标签”入口 + 弹窗标签列表 + 确定按钮。
- 用户下拉菜单 DOM 常驻，靠 `.open` class 显示；退出按钮隐藏时可用 `click(force=True)` 触发。
- 发帖每轮只发 1 篇，规避 BUG-003 的严格限流。
- 网络抖动用 `goto_retry` 重试 3 次。

## 5. 性能测试（JMeter）

只压读接口，不压发帖写接口（写接口限流会先触发 429，测到的是限流而不是性能）：

| 并发 | 总请求 | 错误率 | 平均响应(ms) | TPS |
|---:|---:|---:|---:|---:|
| 5 | 1,250 | 0% | 304 | 15.7 |
| 10 | 2,500 | 0% | 658 | 14.7 |
| 20 | 5,000 | 0% | 1,336 | 14.7 |

观察与边界：

- 20 并发内无超时、无连接异常；响应时间随并发近似线性增长，TPS 在 5 并发附近已接近上限。
- 搜索接口最慢（20 并发 p90 约 2.4s），与 BUG-001 同源，推测为数据库全表 LIKE 查询无索引。
- 压测在共享的公网练习环境完成，无服务器权限；服务端规格、网络链路与其他访问均不可控。
  **TPS ≈ 15/s 只是本次观测值，不能推断为产品固有限制。**
- 上述数据来自 2026-09-02 优化前脚本；09-15 对 JMX 做了优化（登录移出循环、补断言、
  参数化），但为保持已发布数字稳定未重跑。公开仓库不提交原始 `.jtl` 与 HTML 报告。

## 6. 缺陷与误报排除

确认 3 条缺陷：

| 编号 | 缺陷 | 等级 | 关联用例 |
|---|---|---|---|
| BUG-001 | 中文搜索失效（中文关键词 0 命中，数字/英文正常） | P1 严重 | TC-030 |
| BUG-002 | 登录接口无限流（错误口令 10 次均 401，无 429、无锁定） | P1 严重 | TC-044 |
| BUG-003 | 发帖限流阈值过严（第 2 帖即 429） | P2 一般 | TC-045 |

同时复核并排除了 3 处疑似缺陷，均未写入缺陷报告：

| # | 疑似现象 | 复核判据 | 结论 |
|---|---|---|---|
| 1 | 帖子详情页脚本判失败，正文长度仅 176 字符 | 单独打开前 5 个帖子核对，页面内容完整；脚本在元素渲染完成前取文本 | 脚本时序误报 |
| 2 | UI 上能点删除，API 却返回 403 | Flarum 的 `canDelete` / `isEmailConfirmed` 与 UI 按钮是两套判据 | 正常设计，非缺陷 |
| 3 | 搜索“1234”命中标题为“软件测试”的帖子 | 打开正文核对，正文确实含“1234”，Flarum 搜索覆盖标题 + 正文 | 命中正确，原判定有误 |

> 这三处用了三种不同判据（脚本自证 / 权限模型 / 内容核对）。自动化报出的失败默认先怀疑脚本，
> 只有证据链闭合才写进缺陷报告。

## 7. 覆盖边界与未测试项

以下范围**未纳入本轮测试**，报告不对其质量作结论：

- 管理员/版主后台（测试账号为普通用户，无管理员权限）；
- 移动端与跨浏览器兼容性（仅 Chrome 桌面端）；
- 安全渗透测试（仅覆盖 XSS 渲染转义与基础 401/403 越权，未做 SQL 注入、IDOR 遍历、CSRF 深度测试）；
- 数据层直连校验（无数据库凭据，改用 API 间接验证发帖后列表/详情是否一致）；
- 长时间稳定性 / 内存泄漏（短时压测，非长稳测试）；
- 写接口性能与并发写场景（受 BUG-003 限流阻断）；
- 邮箱激活/未激活账号的完整权限落差、第三方登录、账号注销等。

## 8. 结论

1. **读场景整体可用**：注册登录、浏览、发帖评论、板块导航、关注通知主链路均通过；
   83 条用例执行率 97.6%，计入 7 条已确认缺陷的预期失败后达成率 95.2%。
2. **中文搜索是高风险点**：核心检索完全失效，且搜索接口并发性能最差，建议优先修复。
3. **登录接口存在安全风险**：失败尝试未见限流或锁定，建议按 IP / 账号维度增加滑动限流与失败锁定。
4. **发帖限流阈值影响正常使用**：建议按频率而非固定次数限流，区分正常用户与滥用。
5. **结论有边界**：未覆盖管理员、移动端、安全渗透与写接口性能；性能数字只代表本次共享环境观测，
   不代表产品生产能力。
